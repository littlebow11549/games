# 2026-11-16 換目標判定與第一次最近優先修正

## 問題與完成
- 原本第一次手動切換直接沿用自動鎖定游標，已自動鎖住最近時會跳第二近。新增獨立manualLockTarget，第一次手動必從最近開始，後續近到遠；關閉／重開鎖定、目標失效或換關重設手動游標。
- 若最近的已是目前鎖定目標，明示「已鎖定最近目標」。只有目前一隻時提示「附近沒有其他目標」；無有效敵人提示「附近沒有可鎖定目標」，附按鈕亮起及返回音，不虛報切換。
- `js/targeting.js` 統一候選判定：未移除、非死亡／出場、已顯示且HP>0、距離有效；目標身體邊緣到主角≤16可選，排序按中心距離，等距保留出生順序。
- `main.js` 自動鎖定改用相同候選來源；目前目標必須仍存在enemies中，清場立即解除，修正換關指向已移除物件。鎖定保留範圍18，比新選16略大，避免邊界來回抖動。
- 無敵人時換目標仍可點以顯示原因；只有暫停、對話、非戰鬥狀態禁用。
- 觸控／滑鼠左鍵 pointerdown立即判定；忽略後續指標click，鍵盤／輔助工具click(detail=0)仍可操作。Y／Shift+Y保留正反向。
- 入口與targeting模組版本更新，無改動音檔、美術與按鈕布局。
